# T5 — 핀 의도 1비트 (버그 / 참고)

> 스펙 SoT: `docs/PRD-0.4.6.md` §T5 · 결정 D2. 계획: `goals/6-046-ux-polish-plan.md`. 이 티켓 밖은 손대지 않는다.

## 목표

핀마다 의도 1비트 `kind: 'bug' | 'ref'`를 붙인다. 기본은 참고(`ref`). 사용자는 핀 메모 행의 **토글 버튼 1개**로 버그/참고를 바꾼다(폼·드롭다운 금지). 버그 핀은 이미지 위 배지가 시각적으로 구분된다. **옛 핀(kind 없음)은 전부 참고로 취급** — 저장된 컨텍스트 팩을 불러와도 깨지지 않는다.

## 순서 (test-first — 먼저 실패 확인)

1. `tests/pin-kind.test.ts` 작성 후 `pnpm test` → **실패 확인**(빨간불). 검증 항목:
   - `pinKind({id:1,x:0,y:0,memo:''})` → `'ref'` · `pinKind({...,kind:'bug'})` → `'bug'`
   - `hasBugPin([])` → false · 참고만 → false · 버그 1개 → true
   - `toggleKind('ref')` → `'bug'`, `toggleKind('bug')` → `'ref'`
   - `generateContextPack`(기존 `tests/context-pack.test.ts`의 `baseInput` 패턴 재사용)에 kind 없는 핀 → `annotations[0].kind === 'ref'` · `kind:'bug'` 핀 → `'bug'`
   - 옛 팩 모양(annotations에 kind 없음)을 `ContextPack` 타입으로 받아도 타입·런타임 오류 없음(hasBugPin 유사 헬퍼가 undefined를 참고로 처리)
2. 구현 → `pnpm test` 전부 초록 · `pnpm build`(버전 동기화 + tsc + vite build) 통과.
3. UI는 순수 함수(pin-kind.ts)로 분리했으므로 DOM 테스트는 요구하지 않는다. 단 `PinMemoList` 토글 버튼의 텍스트·aria-pressed 전이는 코드로 명확히.
