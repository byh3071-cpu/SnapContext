# T2 — 프롬프트 다이어트 (스마트 디폴트)

> 스펙 SoT: `docs/PRD-0.4.6.md` §T2·결정 D3. 계획: `goals/6-046-ux-polish-plan.md`(2-B). 용어 SoT: `docs/GLOSSARY.md`. T5의 `src/context-pack/pin-kind.ts`(`hasBugPin`·`pinKind`)를 사용한다.

## 목표

기본 프롬프트 = **URL + 핀 메모(본문 최상단) + 요청 1줄**. 브라우저(UA)·화면 크기(뷰포트)·캡처 방식·핀 좌표(%)는 **버그 리포트 템플릿이면서 버그 핀이 1개 이상일 때만** 포함. 형식적 4항 지시문은 요청 1줄로 축소. 설정 토글 없음(D3). 정보 손실 탈출구는 T1의 "자세히 보기".

## 허용 파일

| 파일 | 할 일 |
|---|---|
| `src/context-pack/prompt-builder.ts` | ctx에 `debug: boolean`(= template==='bug' && hasBugPin(pack.annotations)) · `lite: !debug` · 각 핀에 `tag`('[버그] ' 또는 '') · `source.userAgent/viewport/captureType`은 debug일 때만 채움(아니면 빈 값) |
| `prompts/templates/bug-report.md` · `refactor.md` · `reference.md` | 구조를 아래 "새 템플릿 구조"로. `{{#if debug}}…{{/if}}`(환경 절·좌표 포함 핀 목록) / `{{#if lite}}…{{/if}}`(좌표 없는 핀 목록). 용어: "핀 주석"→"핀 메모", "캡쳐 방식"→"캡처 방식", "스크린샷"→"캡처 이미지". frontmatter `date`는 2026-08-29 |
| `src/context-pack/template-engine.ts` | 원칙적으로 무변경. `{{#if}}` 안의 `{{#each}}`가 현재 엔진에서 렌더되는지 먼저 테스트로 확인 — 안 되면 최소 수정(테스트 동반)하고 보고에 명시 |
| `tests/context-pack.test.ts` | 기존 `buildTemplatePrompt` 검증 갱신 + 아래 신규 |

## 새 템플릿 구조 (3종 공통 골격)

```text
# <제목>
- URL: {{source.url}}  (reference는 페이지 제목도)
{{#if pins}}
## 핀 메모
{{#if lite}}{{#each pins}}- **핀 {{id}}**{{tag}}: {{memo}}{{/each}}{{/if}}
{{#if debug}}{{#each pins}}- **핀 {{id}}**{{tag}} ({{x}}%, {{y}}%): {{memo}}{{/each}}{{/if}}
{{/if}}
## 요청
<템플릿별 1줄: bug=핀 메모의 문제 원인과 수정안을 제안해주세요 / refactor=핀 메모 부분의 개선안을 코드로 제안해주세요 / reference=핀 메모 부분의 구조를 분석하고 우리 프로젝트에 맞게 구현해주세요>
{{#if context.userNote}}
## 추가 메모
{{context.userNote}}
{{/if}}
{{#if debug}}
## 환경
- 뷰포트: … · UA: … · 캡처 방식: …
{{/if}}
[첨부: 캡처 이미지]
```

(`{{tag}}`는 `[버그] `처럼 앞뒤 공백 포함 여부를 렌더 결과로 확인해 자연스럽게.)

## 순서 (test-first)

1. `tests/context-pack.test.ts`에 먼저 추가 → **실패 확인**:
   - bug 템플릿 + `kind:'bug'` 핀 → 결과에 UA·뷰포트·좌표(`%`) 포함
   - bug 템플릿 + 참고 핀만 → UA·뷰포트·좌표 없음, 핀 메모는 있음
   - refactor/reference + 버그 핀 → UA·뷰포트 없음(디버그는 bug 템플릿 한정)
   - 핀 메모 절이 요청 절보다 앞에 온다(`indexOf` 비교)
   - 4항 번호 지시문(`\n1. `~`4. `) 없음 · "핀 주석"·"캡쳐"·"스크린샷" 문자열 없음
   - userNote 있으면 추가 메모 절 렌더, 없으면 절 없음(기존 유지)
2. 구현 → `pnpm test`·`pnpm build` 통과.
