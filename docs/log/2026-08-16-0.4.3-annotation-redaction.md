## critic 루프 실측 (M 티어링의 값어치)

1차 critic(Playwright 실측 포함)이 **게이트 전부 green인데도 불통과** 판정 — 구멍은 전부 유닛테스트가 닿지 않는 UI 배선에 있었다:

- **치명**: `MIN_DRAG_PCT=1%` 임계가 가리기에도 적용 → 텍스트 한 줄 폭의 얇은 바가 **무통보 폐기** → 비밀이 그대로 업로드. 1000×6000 캡처에서 문턱이 원본 60px에 달함(% 임계는 이미지가 길수록 커짐). → 표시 4px 절대값으로 분리 + 폐기 시 토스트.
- **높음**: 주석 드래그마다 유령 핀(+포커스 강탈) — `preventDefault`는 Chrome click을 못 막음, canPin 게이트에 도구 조건 추가로 해결. / bake 파이프라인 테스트 0건(인자 지워도 131 green인 뮤테이션 무방비) → fake canvas 픽셀 계약 + 소스 정적 계약으로 폐쇄. / 히스토리 복원 시 가리기 소실 무경고 → hasAnnotations 조건부 고지.
- 재검증(fork): 뮤테이션 재주입이 정확히 red(141/142)로 잡힘 확인, 얇은 바 재실측 커밋 성공, 회귀 0 → **통과**.

## 교훈

1. **파괴적(보안) 동작의 입력 임계값에 % 사용 금지** — 이미지 크기에 비례해 문턱이 커져 "가장 흔한 사용 모양"(얇은 바)이 걸린다. 절대 px + 폐기 시 명시 통보가 계약.
2. **게이트 green ≠ 안전** — 구멍은 전부 테스트가 닿지 않는 UI 배선에 있었다. critic의 실브라우저 실측(esbuild 번들+Playwright 프로브)이 유닛 142개가 못 잡는 치명 결함을 잡음.
3. **redaction 정론**: 모자이크·블러는 Depix·Unredacter로 복원됨 — 솔리드 박스만. bake는 신규 인코딩(aCropalypse 방지). 조사 출처는 PRD-0.4.3.
4. node 테스트 환경에서 canvas 계약 검증: getImageData가 실제 Uint8ClampedArray를 반환하는 fake canvas면 순수 함수 실경로 검증 가능.
