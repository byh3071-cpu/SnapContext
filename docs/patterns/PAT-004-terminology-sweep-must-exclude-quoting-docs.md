증상: 문서 전수 치환(캡쳐→캡처 등)이 승인된 PRD의 용어 표(금지어 열)·grep 실측 인용문·용어 사전·게이트 정규식 자신까지 바꿔 "확정 용어 = 금지 용어"가 되고, 같이 만든 금지어 게이트가 원복을 빨간불로 막아 훼손이 고착된다. 단위 테스트·타입검사·빌드·게이트 전부 초록.
원인: 치환 범위를 "docs/** 전수"로 잡고, 금지어를 **의도적으로** 담아야 하는 문서(용어 사전의 금지 열, PRD 결정 표, 독푸딩 원장, 티켓, 게이트 스크립트, 과거 grep 실측 인용)를 구분하지 않음. 게이트도 같은 범위를 검사해 오류를 잠금.
해결: |
  1. 치환 전에 "금지어 인용 문서" 제외 목록을 명시(예: docs/GLOSSARY.md · docs/PRD-<ver>.md의 결정 표 · docs/dogfood/** · docs/tickets/** · scripts/check-goal-*.mjs · 과거 실측 인용 줄).
  2. 게이트는 같은 제외 목록을 공유하되, 통째 제외보다 표·인용 블록 단위 예외가 정밀하다.
  3. 승인 문서(PRD)는 치환 후 `git diff`로 결정 표 무변경을 확인하고, 이상적으론 바이트 동일 복원(`git show <base>:<file>`).
  4. 적대 검증에서 "게이트 양성·음성 뮤테이션 각 3종"을 돌려 게이트 자체를 검증한다.
적용조건: 용어·맞춤법 전수 치환 + 재유입 게이트를 같은 변경에서 만들 때. 특히 워커(AI)가 자동으로 수행할 때.

# PAT-004 — 용어 일괄 치환은 "금지어를 인용하는 문서"를 먼저 제외한다

## 재현

1. `docs/**`에 "캡쳐"가 59건. 승인된 `PRD-0.4.6.md`의 결정 표에 `| 캡처 | 캡쳐·스냅·스크린샷 |`(확정 | 금지) 행이 있다.
2. 워커가 `docs/**` 전수 치환 → 표가 `| 캡처 | 캡처·스냅·스크린샷 |`로 변해 확정=금지. 같은 커밋에 "docs 캡쳐 0건" 게이트 신설.
3. 사람이 표를 원복하면 게이트가 `✗ docs 캡쳐 1건(PRD-0.4.6.md)`로 빨간불 → 다시 망가뜨리게 됨.

## 왜 게이트가 못 잡나

게이트는 "금지어 0건"만 본다. 금지어가 **있어야 하는** 자리(용어 사전 금지 열·결정 표·실측 인용)를 구분할 방법이 없다. 단위 테스트·타입검사·빌드는 문서를 보지 않는다.

## 체크리스트

- [ ] 치환 대상 glob에서 GLOSSARY·PRD 결정 표·원장·티켓·게이트 스크립트·과거 실측 인용을 제외했는가
- [ ] 치환 후 승인 문서(PRD·ADR)가 base와 diff 0인가(결정 표 기준)
- [ ] 게이트 제외 목록이 치환 제외 목록과 같은가, 이월 항목(예: `docs/store/`)을 제외로 숨기지 않았는가
- [ ] 게이트에 양성 3종(금지어 주입 → 빨간불)·음성 3종(정당한 인용 → 초록) 뮤테이션을 돌렸는가
