# ADR-021: 파괴적 redaction — 솔리드 박스 bake, 오버레이·블러·모자이크 금지

## 상태

승인 — 2026-08-16 PRD-0.4.3 승인에 포함. D1은 조사로 상향(원안 모자이크 → 솔리드 박스).

## 결정 질문

캡처 속 비밀(토큰·이메일·잔액 등)을 업로드 전에 가리는 도구는 어떤 방식이어야 복원 불가를 보장하는가?

## 범위와 비범위

- 범위: 가리기 도구의 렌더 방식, bake 시점, 내보내기 경로 계약
- 비범위: 표현용 주석(화살표·형광펜·자유선)의 시각 스펙, 자동 비밀 탐지(OCR)

## 맥락

- 0.4.2로 "내 토큰의 AI만 내 캡처"가 됐지만, 캡처 픽셀 안의 비밀은 그대로 worker·AI에 전달된다.
- [웹/외부] 픽셀레이션(모자이크)은 안전하지 않다 — Depix·Unredacter가 픽셀레이션된 텍스트를 실복원했고, Bishop Fox 권고는 "검정 박스만, 픽셀레이션·블러·스월 전부 금지"다. 가우시안 블러의 AI 복원 연구도 다수다.
  - https://bishopfox.com/blog/unredacter-tool-never-pixelation
  - https://positive.security/blog/video-depixelation
- 편집 후 파일에 원본 바이트가 잔존하는 사고 사례(aCropalypse, CVE-2023-21036)가 있다 — 가림이 픽셀에서 참이어도 파일 레벨에서 새면 무효.

## 결정

1. **가리기 = 불투명 솔리드 박스 단일**. 모자이크·가우시안 블러는 제공하지 않는다(안전해 보이는 불안전 옵션을 주지 않는다). 도구명도 "블러"가 아닌 "가리기".
2. **오버레이 금지 — 캔버스 bake**: 내보내기 산출물은 가림 영역 픽셀이 상수로 대체된 비트맵이다. CSS·DOM 오버레이·별도 레이어 저장은 금지(비밀이 원본 채로 새는 경로).
3. **bake 시점 = 내보내기**: 편집 중에는 벡터 데이터로 유지(undo 가능). 다운로드·클립보드 복사·`내 AI에 저장` 업로드의 **모든 경로가 단일 bake 파이프라인**(`renderAnnotatedPngBlob`)을 지난다. 우회 경로 0.
4. **신규 인코딩 보장**: bake 산출물은 `canvas.toBlob`으로 새로 인코딩한 PNG — 원본 바이트·편집 메타데이터가 파일에 잔존할 수 없다(aCropalypse 류 원천 배제).
5. 로컬 히스토리의 원본은 유지한다 — 위협모델은 "서버/AI로 새는 것"이고 로컬은 사용자 소유.

## 결과

- 업로드 전 프라이버시 원천차단이 "재미 기능"이 아닌 보안 계약이 된다.
- 테스트 계약: bake 후 가림 영역 픽셀 전수 = 지정 단색, 내보내기 3경로 파이프라인 단일성, 산출 PNG에 원본 바이트 잔존 없음.
- critic 게이트(M 티어링): bake 산출물에서 원본 유추 불가·우회 경로 부재를 적대 검증.
